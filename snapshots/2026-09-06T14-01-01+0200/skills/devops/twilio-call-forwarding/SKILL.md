# Twilio Call Forwarding

Set up pure call forwarding for a Twilio phone number — inbound calls get `<Dial>`'d to a configurable target number. All scripts live **inside** the existing Hermes agent directory (`/opt/hermes-*/twilio/`), not as a separate project.

## Architecture

```
Caller ──► Twilio Phone Number ──► TwiML Bin (<Dial>) ──► FORWARD_TO_NUMBER
                                   │
                              [Status Callback] ──► server.js → calls.log
```

## Files to create

All under `/opt/hermes-*/twilio/`:

```
twilio/
├── package.json          # dep: "twilio" SDK only
├── setup.js              # One-time: create/update TwiML Bin + assign as Voice URL
├── set-forward.js        # CLI: change forwarding target (node set-forward.js +49...)
├── server.js             # (optional) HTTP server for status callback logging → calls.log
├── calls.log             # generated by server.js
└── .last-bin-sid         # generated by setup.js (SID cache)
```

## Env vars to add to the agent's `.env`

```
# =============================================================================
# TWILIO — Call forwarding for <phone number>
# =============================================================================
TWILIO_ACCOUNT_SID=
TWILIO_AUTH_TOKEN=
TWILIO_PHONE_NUMBER=+1XXXXXXXXXX
FORWARD_TO_NUMBER=+49123456789
STATUS_CALLBACK_URL=
```

## Setup steps

1. `cd /opt/hermes-*/twilio/ && npm install` (installs twilio SDK)
2. Edit `../.env` → fill in `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `FORWARD_TO_NUMBER`
3. `node setup.js` — creates TwiML Bin with `<Dial>FORWARD_TO_NUMBER</Dial>`, sets Voice URL on phone number

## Runtime CLI

```bash
# From /opt/hermes-*/twilio/:
node set-forward.js +49123456789   # change forwarding target (updates .env too)
```

## Call logging (optional)

`node server.js` starts an HTTP server on port 3000. Set `STATUS_CALLBACK_URL` in `.env` to a publicly-reachable URL pointing to `/status` on this server.

## Critical workflow preference: INTEGRATE, don't create separate

**When the user already has a Hermes agent** (e.g. `/opt/hermes-2/` or `/opt/hermes-1/`) and asks for a telephony/service feature:

- **DO** create the files inside the agent's directory tree (`/opt/hermes-*/twilio/`)
- **DO NOT** create a separate standalone project in `/opt/` or elsewhere unless the user explicitly asks for it
- **DO** add the env vars to the agent's existing `.env` file
- The agent's existing `.env` needs user consent to modify (it's guarded; ask before editing)

Rationale: The user manages one agent with one `.env`, one set of dependencies, one directory. Splitting into separate projects means separate package.json, separate node_modules, separate env management — more overhead, not simpler.

## Pitfalls

- **Security guard on `.env`:** Terminal commands that write to the agent's `.env` may be blocked. Ask the user for explicit consent.
- **Status callback URL must be public:** Twilio won't reach localhost. Use ngrok, a reverse proxy, or a public IP.
- **E.164 format:** Phone numbers must be `+<country><number>` — no spaces, parens, dashes. Validation regex in set-forward.js: `/^\+[1-9]\d{6,14}$/`
- **Zero AI requirement:** This skill is for PURE forwarding (<Dial> only). If the user also wants voice agents/ElevenLabs, that's a separate concern and should not be mixed into the TwiML Bin.
